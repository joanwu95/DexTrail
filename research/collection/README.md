截至 2026-10-02 已整理 200 个硬件与配置条目（198 份笔记 + 网站原有 Shadow Classic/LEAP），含研究夹爪与假肢。新增资料均为 partial，阅读范围各有不同。先从 [资料索引](index.md) 阅读；数量口径、校验和待补内容见 [最新进度](progress.md)。

目标：广泛覆盖工业产品和学术研究平台，并提供能够读懂的技术内容，不只列出处。先积累与版式无关的 Markdown/YAML 资料；本轮不修改网页、不上传 GitHub。

## 工作顺序
1. 每轮先阅读 progress.md 和 queue.yaml，避免重复搜索。
2. 每批处理 2–4 个型号，或深挖 1–2 个已有型号。既扩大覆盖，也补足解释深度。
3. 第一优先级：Shadow Classic、LEAP v1 尚未解释清楚的指标；随后 Allegro、DLR、Barrett、Xynova 等。
4. 每个型号独立文件。不同代际、标准/选配、研究改装版本分别记录。候选型号不等于已验证产品。
5. 每批写入已完成内容与下一步，失败时也保留检查点。用户已改为要求当前会话连续执行；原每小时8次的夜间任务已暂停，不用定时等待代替当前工作，不要求用户逐批输入继续。

## 每个条目的结构
身份与版本；机械结构；驱动与传动；位置/力/触觉感知；控制；仿真与软件；操作任务和实验结果；优势与代价；外部评价；媒体与模型链接；缺失项；来源与核查日期。

每个非空技术指标必须说明：原文实质内容、通俗解释、单位与测量条件、适用版本、来源章节。解释要回答测什么/怎样实现/数字什么意思/用途/边界。分清分辨率与精度、腱力与指尖力、关节数与主动自由度、仿真结果与实物结果。

## 证据要求
- 官方文档、原始论文、技术报告、作者或厂商仓库优先。搜索摘要只作线索。
- 明确标注 fact（来源陈述）、reported_limitation（文献报告局限）、interpretation（工程解释）。厂商宣传不当作独立验证。
- 记录 URL、标题、章节、版本/日期、核查日期。转述实质内容，不复制整篇文档；遵守来源引用限制。
- 无资料写待核验，并记录已经搜过什么；不要凭空补齐。优缺点必须有比较对象或适用任务，不强行给所有产品写负面评价。
- 实验结果绑定型号、控制器、传感配置、物体、真实/仿真、试验次数、成功判据，不能跨协议排成功率。
- 模型链接注明格式、维护方、版本、许可及本地运行状态。只登记链接，不下载媒体、大模型、仓库或执行第三方代码。
- 不使用账户额度重置卡，不购买额度；遇额度限制保存进度，等待可执行时续接。
